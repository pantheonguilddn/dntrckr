Guild administration

Pantheon Admin Console

Manage approved Discord accounts, player ownership and character registrations, registered dungeon tasks, optional completion exclusions, and the one-time JSONBin migration. Do not share the old JSONBin master key; it is used only for the one-time import form and is not saved by this page.

1. Add an approved Discord account

Use the account's numeric Discord user ID, not a username. The member does not need to configure cloud sync after being allowlisted.

Pantheon normally matches a Discord profile name to the same-named Member Roster owner automatically. Use Roster match name only if those names differ; enter the exact owner name once. To copy a Discord ID, enable User Settings → Advanced → Developer Mode, then right-click the user's profile and choose Copy User ID.

2. Tool launcher

The sidebar has been removed from member accounts. Launch tools from here when working as an administrator. Each link opens Pantheon in a separate tab, where the app checks the signed-in role again. Global changes to dungeon tasks, loot weights, and version savepoints are restricted to administrators.

3. Character registration & Main designation

Admin-only controls for every member’s registered IGNs, class / job, and Main designation. All registered characters are automatically included in Tracker. Changing a registration requires that member to confirm their details again at their next login.

4. Player ownership audit

Manage which enabled Discord account is linked to every Member Roster entry. You can assign, replace, or clear a link. These actions only change account ownership; character registrations and saved progress are preserved.

A suggested account is based only on an exact allowlist-label match. It is never assigned automatically. For each unresolved owner, verify the person before linking their Discord account. If someone has not been added to the allowlist, add or enable their account above first.

5. Extra Dungeons

This is the shared exclusion list for every registered dungeon task. Checked tasks remain visible in the Tracker but default to muted N/A for every character. A character owner can right-click that character’s cell to opt in only that character for completion calculations and Share Bounties; everyone else stays N/A. The optional checkbox in Dungeon Registration adds the task to this same list immediately. Daily tasks remain outside weekly completion math. Existing marked/completed cells are preserved.

Only administrators can edit this list. This is the single shared source for default N/A/exclusion behavior. Saving updates the same policy used by Dungeon Registration and applies to every member after their next shared-data refresh.

6. Dungeon Entries, Drops & Rewards

The activity reference editor has been merged into Dungeon Registration. Register a task first, then select it in the same panel to edit entry counts, milestones, party size, run time, service availability, materials and notable drops, weekly rewards, and Activity Insights recommendations. This keeps dungeon names and details linked instead of maintaining two separate name lists.

Open Dungeon Registration & Details

Existing activity profiles are preserved and remain linked by their names and aliases. Newly registered tasks automatically receive a blank details profile. No old reward or drop notes are deleted.

7. Move the old guild record from JSONBin to D1

Run this once, from an administrator session, to copy the existing tracker and revision journal into Cloudflare D1. The target records are the private IDs used by the new Pantheon backend. This leaves the old JSONBin records untouched as a backup.

8. Initialize an empty database instead

Use this only if there is no JSONBin data to migrate. It creates a clean, empty tracker record. It will not overwrite an existing main record.
